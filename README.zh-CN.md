# ClearWeave

**一个同时处理中文、英文和中英混排的去 AI 味 Skill。**

[English](README.md) · [技能正文](skills/clearweave/SKILL.md) · [32 项来源取舍](docs/sources.md) · [实测报告](docs/evaluation.md)

ClearWeave 将清晰表达（Clear）与多种方法的融合（Weave）放在同一个名字里。它用一套共用流程保护原意，再按中文、英文和学术场景处理具体表达，因此不需要维护两份容易出现分歧的独立技能。

它是让 AI 助手遵循的编辑规则包，附带一个可选的本地 Python 检查脚本。实际改写、翻译和审稿由宿主模型完成，脚本只做有限的表达提示和字面变化检查。

## 真实能力

| 能力 | 实际行为 |
| --- | --- |
| 中文、英文、中英混排 | 默认保留各段语言；中文提问不会自动把英文论文翻成中文。简繁体和英美拼写随原文或明确要求。 |
| 去套话、翻译腔和空泛表达 | 根据语义功能修改铺垫、重复、名词化和拗口句法，保留必要的连接、术语和对照。 |
| 轻度润色与结构重写 | 默认做最小必要修改；用户要求时可重排结构。原文已经自然时允许不改。 |
| 原意保护 | 核对主体、数值、单位、否定、范围、条件、引用、确定程度、因果关系和计划／完成状态。这是编辑流程，不能保证零失误。 |
| 学术与技术写作 | 去掉无信息的自我辩护，同时保留真实局限、不利结果、合理不确定性和必要的术语重复。 |
| 文体适配 | 学术／技术、商务／公文、新闻／解释、博客／社媒分别处理，避免所有文体都被改成口语。 |
| 双向翻译 | 在明确请求后进行中英互译，保留源文的事实承诺、语气和限定。 |
| 参考作者样稿 | 学表达密度、正式程度和节奏，不把样稿的经历、数据或观点搬进目标稿。 |
| 诊断与审稿式检查 | 给出具体位置、问题和修法；把已发现的问题与尚待核实的疑问分开。 |
| 根据材料起草 | 只组织已有材料，不补造实验、指标、来源或个人经历。 |
| 本地辅助检查 | Python 3.10+ 标准库实现，无第三方依赖；提示部分套话候选并比较受支持的字面保护内容。 |

技能本身不要求联网、API Key、检测器账号，也不依赖安装那 32 个上游项目。宿主应用自己的数据与权限规则仍然适用。

## 安装与使用

可安装目录是 **`skills/clearweave/`**，结构遵循 [Agent Skills 规范](https://agentskills.io/specification)。

### 安装到 Codex 项目

```bash
git clone https://github.com/PresleyRen/clearweave-skill.git
cd clearweave-skill
python3 tools/install_skill.py --project /你的项目绝对路径
```

安装器复制到 `<项目>/.agents/skills/clearweave`，已有同名目录时会停止，不覆盖内容，不改全局设置，也不安装外部依赖。更新前请检查差异，再明确替换旧版本。

在 Codex CLI／IDE 中使用 `$clearweave`。已安装此技能的 ChatGPT 环境可通过技能选择器使用。安装位置和选择方式以[宿主官方文档](https://learn.chatgpt.com/docs/build-skills)为准；GitHub 仓库与 Release 发布不等于已上架插件目录。其他支持 Agent Skills 的宿主可以尝试加载目录，本版本尚未逐一验证这些客户端。

**中文润色：**

```text
$clearweave
给下面这段去 AI 味，保留原意、中文和正式程度，只给正文：
[原文]
```

**英文论文、中文说明：**

```text
$clearweave
润色下面的英文论文，正文保留英文，修改说明用中文。
保留数值、引用、条件、局限和证据强度：
[原文]
```

**其他模式：**直接说明“只诊断不重写”“翻译成台湾读者习惯的繁体中文”“按以下样稿的语气改写”“根据这些笔记起草”或“像严格审稿人一样检查论证”。这些是自然语言请求，不是额外实现的一组斜杠命令。

## 检查脚本能检查什么

在仓库根目录运行：

```bash
python3 skills/clearweave/scripts/clearweave_check.py lint draft.md --format json
python3 skills/clearweave/scripts/clearweave_check.py compare original.md revised.md --format json
```

`lint` 给出行列位置和可疑表达。它不因为出现被动句、三项列举、破折号或正常技术词就判错，也不自动改写。没有命中不等于文字已经很好。

`compare` 比较受支持的数字、单位、引号内容、URL、引用标记、代码和公式等字面片段的增减。两个数值分别属于谁、否定是否改变、条件是否移错等问题，仍可能逃过检查；结果始终标明需要语义复核。翻译或用户要求的引用格式变化也可能产生合理差异。

具体语法范围、额外保护列表、标准输入、JSON 字段和退出码见[脚本文档](skills/clearweave/references/tooling.md)。两个命令均不修改原稿。

## 32 项来源如何融合

范围是此前清单中的 **32 个实现：28 项直接相关、4 项写作辅助**。这不是全网总数，也不代表 32 种相互独立的方法。部分项目具有明显同源关系。

| 上游常见冲突 | ClearWeave 的处理 |
| --- | --- |
| 全删限定语／处处加保留语 | 保留影响结论的限定，删掉空洞和重复的道歉。 |
| 禁词、禁被动、禁破折号、禁三项并列 | 根据语义功能和文体判断，正常用法可以保留。 |
| 强行加情绪、故事和“人设” | 保留作者已有声音，非虚构内容不补造经历。 |
| 刻意打乱句长、追逐检测分数 | 以清楚、准确和文体适合为目标，不设句长分布或检测器达标阈值。 |
| 只讲最有利的研究故事 | 保留影响结论的不利结果，不事后更换评价标准制造优势。 |
| 改到所有句子都不一样 | 一次编辑，最多再做一次针对性修正；发现失真就回退，允许不改好句。 |

[完整审计记录](docs/source-audit.json)逐项列出来源、采用内容、拒绝／修改内容、落入的模块、同源关系和许可观察。检查针对读取时的 main 分支，没有声称固定了所有上游提交，也没有把上游自报效果当成 ClearWeave 实测结果。

## 测试与证据

[实测报告](docs/evaluation.md)公开原始输入、两组实际输出、匿名复审判断、局限和修复记录。[测试协议](evals/PROTOCOL.md)说明普通写作流程与技能流程如何在独立上下文中执行。

初始 18 项对照中，复审者认为 ClearWeave 的 18/18 项、普通流程的 17/18 项保留了原意；两组各有 1 项更受偏好，16 项持平。随后针对产品说明的空泛开场细化规则，新增 4 项检查均保留原意并满足任务要求。这个小样本没有证明技能普遍优于普通提示词；原始输出与修改前的规则快照均保留。

可在本地重复运行确定性检查：

```bash
python3 -m unittest discover -s tests -v
python3 tools/validate_repo.py
```

行为测试采用原创虚构材料，每个请求、每个条件保留一次实际结果；测试使用同一宿主模型体系，评判者也是模型，没有真人编辑盲评。它能说明这些样例中观察到的表现，不能推导为全场景优于普通提示词，更不能推导为任何商业检测器的通过率。

## 已知边界

- 不判断作者是否为 AI，不提供 GPTZero／Turnitin 集成或“人类文本百分比”。
- 常规润色不核实文献和事实真伪；明确要求事实核查时，仍需合适证据与宿主工具。
- Python 脚本采用保守的正则匹配，不是完整的 Markdown、LaTeX、引用、单位或语义解析器。
- 实际效果受宿主模型能力影响；自动触发和所有第三方客户端尚未逐一验证。
- 原生处理纯文本和 Markdown。DOCX、PDF、幻灯片的版式保留需要另外的文档工作流。
- 长篇论文、专业术语、细微含义变化及法律／医学准确性仍需专业复核。
- 本版本设计范围为中英文，不承诺其他语言同等表现。
