`skills/clearweave/scripts/clearweave_check.py` 是一个可选的 Python 3.10+ 标准库工具。它读取 UTF-8 文本，只向标准输出生成报告；没有网络访问、外部依赖或原稿写入操作。

- `lint` 找到少量中英文表面表达候选，供作者或编辑逐项判断。
- `compare` 对支持的受保护字面片段做计数比较，提示新增或丢失。

这两项检查都不能判断作者身份或生成模型，也不能证明语义完整。所有报告都包含 `semantic_review_required: true`。本工具不输出 AI 概率，不自动改写，不把没有候选或没有字面变化称为文稿“通过”。

## 命令接口

在仓库根目录运行：

```bash
python skills/clearweave/scripts/clearweave_check.py lint INPUT --language auto --format text
python skills/clearweave/scripts/clearweave_check.py compare ORIGINAL REVISION --format json
```

| 参数 | 含义 |
| --- | --- |
| `INPUT`、`ORIGINAL`、`REVISION` | UTF-8 文件路径；可以用一个 `-` 读取标准输入 |
| `--language auto\|en\|zh\|both` | 仅用于 `lint`，默认 `auto`；`auto` 根据保护区之外的常见汉字和拉丁字母选择规则集 |
| `--format json\|text` | 默认 `text`；`json` 适合其他程序读取 |
| `--protect-file FILE` | 额外保护词表，两种命令都支持；每行一个完整的字面字符串 |
| `--help` | 显示主命令或子命令帮助，不读取输入文件 |

`compare` 的两个输入中最多有一个 `-`。`--protect-file` 必须是文件路径，不能再从标准输入读取。相对路径按当前工作目录解释。

标准输入示例：

```bash
python skills/clearweave/scripts/clearweave_check.py lint - --language both --format json
python skills/clearweave/scripts/clearweave_check.py compare original.md - --format json
```

向进程提供文本并结束标准输入后即可取得报告。原稿路径和修订稿路径可以相同，工具仍只读取文件。

## `lint` 报告

候选记录含 `rule_id`、`line`、`column`、`excerpt` 和 `reason`。行号、列号从 1 开始，列按 Unicode 码点计数，不按屏幕宽度计算；中文全角字符和制表符不会被当成多个显示列。

当前规则只覆盖部分常见开场、空泛赞美、强调语和收尾。例如，中文的强调短语可能被列为候选，原因会提醒编辑保留后面的真正限制。总结连接词和邮件结尾可能完全合适，候选不是错误判决。

中文短语规则目前主要采用简体词形，对繁体词形的覆盖有限。`--language zh` 只选择规则集，不会转换简繁或改写地区用语；繁体文稿没有命中，也需要正常的编辑复审。

规则没有禁止 `robust`、`significant`、`framework`、被动句、三项列举或正常破折号。没有命中候选只说明未命中当前短语规则，不能说明表达自然、论证完整或文章没有其他问题。

## 受保护区域

`lint` 跳过识别到的保护区。`compare` 比较这些区域的原始字符串，包含其内部空格、符号和换行，不做同义替换、数值标准化或单位换算。

| 类型 | 当前支持 |
| --- | --- |
| Fenced code | 行首最多三个空格，至少三个反引号或波浪号；结束围栏为同一字符且不少于起始长度；未闭合围栏保护到文件末尾 |
| Inline code | 相同长度反引号围成的行内代码，可包含较短的反引号串；配对不会跨越空行或本工具识别的行首围栏、块引用边界 |
| YAML frontmatter | 文件开头的 `---` 块，允许 UTF-8 BOM，需以 `---` 或 `...` 闭合；只识别块边界，不验证 YAML 内容 |
| Markdown blockquote | 行首最多三个空格后的 `>`；相邻带标记行作为一个区块 |
| 引号 | 成对的英文双引号、中文弯双引号及 `「」`、`『』`；英文双引号支持反斜杠转义；英文撇号不作为引号 |
| 常见数学表达 | `$...$`、`$$...$$`、`\(...\)`、`\[...\]`；`equation`、`align`、`gather`、`multline` 及其星号版本，另有 `math`、`displaymath` 环境 |
| URL | `http://`、`https://`、`ftp://`、`mailto:`；保留内部成对括号，按启发式移除外围未配对括号和句尾标点 |
| Markdown 目标 | 简单链接／图片的内联目标、尖括号目标和引用式链接定义；支持目标内部的平衡圆括号及相对路径 |
| 数字 | 阿拉伯数字、正负号、小数、千位逗号、科学计数法、百分号与部分常见单位；数字可紧邻中文字符 |
| 引用标记 | 数字方括号引用、简单 Pandoc `[@key]` 标记、常见 LaTeX cite 命令，以及有限的英文作者年份括号形式 |
| 裸 `@key` | 保守识别 `@smith2024`、`-@doe:2025` 等字面标记，单独标为 `at_key`；不宣称这些标记一定是引用 |
| 自定义 | keep 注释块与 `--protect-file` 中指定的字面字符串 |

常见单位表包括时间、长度、质量、温度、数据量、频率、币种和部分中文量词。例如 `-5°C`、`1,024MiB`、`2e+3ms`、`5%`、`12条`、`3 m/s²`。这是有限列表，不是完整的科学单位或数字语法解析器。

结构区域按原文顺序识别，已识别的外层区域会屏蔽其内部的其他结构定界符。例如 YAML 内的围栏示例、围栏或行内代码内的 keep 示例，以及 keep 块内的围栏，都不会重新打开一个延伸到后续正文的区域。keep 块自身仍按成对的 keep 标记处理嵌套。引号或公式的起止标记不会取自这些结构区域内部，但外部的成对引号仍可包住其中的行内代码，保留整段直接引语。URL、引用键和数字识别则在结构区域之间运行；这套处理规则不等于完整 Markdown 解析。

裸 `@key` 以 ASCII 字母或下划线开头，后续接受 ASCII 字母、数字、下划线，以及由点、冒号、斜杠或连字符连接的片段。识别时避让常见邮箱地址中的 `@` 和反斜杠转义的 `\@`。然而 `@editor` 既可能是引文键，也可能是社交提及；工具没有文献库来消除歧义，所以统一作为 `at_key` 字面保护。它的变化只表明该字符串有变化，不证明文献引用发生变化。复杂的邮箱、Unicode 引文键及完整 Pandoc 引用语法不保证识别。

完整的外层保护区只计一次，不再把其中的数字、URL 等重复计入报告。如果两个识别区域部分重叠，工具将它们合并为一个 `overlapping_protection` 区域。报告的类别可能因围栏或其他边界变化而改变。

## 自定义保护

对多行或完整段落使用 keep 注释：

```markdown
<!-- clearweave:keep -->
此处放需要保留的原文、合同措辞或指定表达。
<!-- /clearweave:keep -->
```

keep 块连同注释标记一起参与字面比较。支持嵌套标记；打开后未闭合的块保护到文件末尾。

也可以准备 UTF-8 词表，例如 `protected.txt`：

```text
Recall@10
指定产品名称
条款中的完整一句话。
```

```bash
python skills/clearweave/scripts/clearweave_check.py lint draft.md --protect-file protected.txt
python skills/clearweave/scripts/clearweave_check.py compare original.md revised.md --protect-file protected.txt --format json
```

空行被忽略，重复条目合并；其他空格和大小写按字面保留。词表没有注释语法，也不解释正则表达式。若自定义字符串已位于较大的保护区中，比较外层完整区块即可。

## `compare` 的结果和退出状态

`changes` 中每条记录给出类型、完整 `literal`、原稿与修订稿中的出现次数、`delta`、`added`／`lost` 状态及位置。`change_count` 是出现次数发生变化的不同字面条目数，不是改动句子数。文本格式会截短过长片段的展示，JSON 保留完整字面字符串。

| 命令结果 | 退出状态 |
| --- | --- |
| `lint` 正常完成，无论有无候选 | `0` |
| `compare` 未发现支持范围内的字面计数变化 | `0` |
| `compare` 发现字面计数变化 | `1` |
| 参数错误、文件读取失败或 UTF-8 解码失败 | `2` |
| `--help` | `0` |

退出状态 `0` 不代表语义通过。单位等价转换也会报告字面变化：`1000ms` 改成 `1s` 会产生一项丢失和一项新增。编辑可以复核并接受有意的合法修改。

## 必须人工或模型复审的边界

**计数不检查角色与顺序。** 把“A 得分 0.8、B 得分 0.6”改成“A 得分 0.6、B 得分 0.8”，两种数值的字面计数相同，工具可能返回 `0`。如果这段原文在显式 keep 块或直接引语中，整段字面变化则会被发现。

**普通正文的意思不在比较范围内。** 支持改成不支持、计划改成已完成、相关改成因果、某人推测改成作者结论，都可能没有字面保护差异。因此即使 `changes` 为空，`semantic_review_required` 也始终为 `true`。

**语法识别采用启发式。** 它不是完整 Markdown、HTML、LaTeX、引用格式或自然语言解析器。缩进代码、复杂嵌套标签、blockquote 的无标记续行、任意 HTML 属性、未闭合引号、某些转义组合、多语言作者姓名及复杂文内引用可能漏检或被过度保护。美元货币和 `$...$` 数学的区分、URL 末尾真实标点与句子标点的区分也有歧义。

**数字与单位覆盖有限。** 英文拼写数词、汉字数词、罗马数字、区域小数格式、任意自定义单位及嵌入某些标识符的数字不保证识别；复合单位和中文数量级表达也没有完整解析。单位或数量级若未被识别，仅数字本身的计数不一定能发现变化。关键表述应加入自定义保护，并继续进行语义检查。

**字面保护不验证真伪。** 原稿本身可能含错误、过期来源或无依据主张；保持相同字面不等于内容可靠。输入全文在内存中处理，当前实现面向普通文稿，没有为超大语料提供流式处理或资源上限保证。

## 本地测试

```bash
python -m unittest discover -s tests -v
```

`tests/test_checker.py` 覆盖接口状态码、保护区跳过、外层结构中的定界符示例、中英文候选、数字与单位、URL 括号、代码变化、裸引文键与常见邮件地址的区分、重复条目减少，以及数值角色互换和否定变化这两个明确盲区。上述命令同时运行仓库中其余确定性测试。这些不是英文或中文写作效果的行为评测，也不是 AI 检测器测试。
